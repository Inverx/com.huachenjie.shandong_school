# LSPosed 模块使用指南

本教程介绍如何在 MuMu 模拟器中安装并使用本项目发布的 LSPosed 模块。

## 当前测试环境

| 组件 | 版本 / 配置 |
|---|---|
| 模拟器 | MuMu 模拟器 |
| Android | Android 12 |
| Root / 管理框架 | Kitsune |
| Kitsune | `v31.0-25fa2159` |
| Zygisk | `NeoZygisk-v2.4-289-release` |
| Hook Framework | LSPosed |
| 定位工具 | FakeLocation `1.3.2` |
| FakeLocation 步频 | `10 steps/s` |
| 兼容模块 | 冰社模块 |
| 项目模块 | 本仓库 Releases 发布的 LSPosed 模块 |

建议尽量按照上面的版本搭建环境，避免因为版本不同出现模块不生效、应用闪退等兼容性问题。

---

## 一、安装模块

首先安装：

- FakeLocation `1.3.2`
- 冰社模块
- 本仓库 Releases 中发布的 LSPosed 模块

安装完成后打开 LSPosed。

---

## 二、设置 LSPosed 作用域

### 冰社模块

进入：

`LSPosed → 模块 → 冰社`

作用域勾选：

- FakeLocation `1.3.2`
- 系统框架

主要用于当前测试环境下的 FakeLocation 兼容性处理。

设置完成后重新启动模拟器。

---

### 本项目 Hook 模块

进入：

`LSPosed → 模块 → 本项目模块`

作用域只需要勾选：

- 闪动校园

不需要勾选其他无关应用。

设置完成以后强制停止闪动校园，然后重新打开。

如果模块仍然没有加载，可以直接重启一次模拟器。

---

## 三、配置 FakeLocation

打开 FakeLocation。

选择：

`路线模拟`

然后在地图上绘制一条测试路线。

建议路线尽量完整、连续，不要出现跨度特别大的定位跳变。

如果需要测试运动相关的数据，可以打开：

`步频模拟`

当前测试环境使用：

`10 步/秒`

这个参数主要是当前版本的测试基线，方便不同环境之间排查问题。

---

## 四、启动路线模拟

路线设置完成以后启动模拟。

如果出现：

- 定位停留在路线起点
- 启动后位置不移动
- 路线模拟没有正常开始

可以尝试：

`启动模拟 → 暂停模拟 → 再次启动模拟`

当前 MuMu Android 12 测试环境中，部分情况下模拟器刚启动后第一次开启路线模拟只会定位到起点，重新启动一次模拟后路线才会正常移动。

---

## 五、打开闪动校园进行测试

确认 FakeLocation 中的位置已经开始移动以后，再打开闪动校园。

建议先检查：

- 应用是否正常启动
- 是否出现闪退
- LSPosed 模块是否正常加载
- 定位是否正常更新
- 路线是否持续移动

如果这些都正常，说明基础环境已经搭建成功。

---

## 六、出现问题怎么排查

如果闪动校园闪退：

1. 先关闭本项目 LSPosed 模块
2. 重新打开闪动校园
3. 判断是否由 Hook 模块引起

如果 FakeLocation 闪退：

1. 检查 FakeLocation 是否为 `1.3.2`
2. 检查冰社模块作用域
3. 检查是否勾选系统框架
4. 重启模拟器

如果 LSPosed 模块不生效：

检查顺序：

`Kitsune → NeoZygisk → LSPosed → 模块 → 作用域`

确保每一层都已经正常加载。

---

## 推荐环境

目前测试较稳定的一套环境：

```text
MuMu Android 12
Kitsune v31.0-25fa2159
NeoZygisk v2.4-289-release
LSPosed
FakeLocation 1.3.2
```

如果使用其他版本出现兼容性问题，可以优先尝试切换到以上环境进行排查。

---

## 注意

本文主要用于 LSPosed 模块兼容性测试、定位接口测试和 Android 逆向研究。

不同版本的：

- MuMu
- Kitsune
- NeoZygisk
- LSPosed
- FakeLocation
- 闪动校园

都可能导致模块行为发生变化，因此出现问题时请优先确认版本是否一致。
